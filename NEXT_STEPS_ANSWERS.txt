## STOCK MARKET KA DON – NEXT STEPS ANSWERS

**Key decisions**

| Area                | Recommended decision |
| ------------------- | ------------------------------------------------------------------------------------ |
| Next release        | Prioritize market-data integrity, reliable signals, and automated testing |
| Backend testing     | `pytest` + `pytest-cov` |
| Frontend testing    | `Vitest` + `Playwright` |
| Coverage            | Start at 70% overall, with stronger coverage for critical trading logic |
| CI/CD               | GitHub Actions for linting, tests, security checks, and builds |
| Security            | Dependency audits, secret scanning, restricted CORS, secure configuration |
| Deployment          | FastAPI container/VM + static frontend hosting |
| Trading data        | Explicitly distinguish live, delayed, cached, simulated, stale, and unavailable data |
| Android             | Verify the actual implementation and build before claiming APK/AAB support |
| Future architecture | Defer Kafka, MLflow, and complex distributed infrastructure until justified |

**Immediate priorities**

- **P0 — Market-data integrity**
  - Remove fabricated fallback prices and indicators. Missing market data must never look like a valid trading signal.
- **P0 — Validate calculations**
  - Preserve OHLCV candle alignment and reject invalid or insufficient indicator inputs.
- **P1 — Establish a quality gate**
  - Add regression tests and CI before expanding AI, backtesting, or Android functionality.
- **P1 — Security and deployment**
  - Audit dependencies and secrets, restrict production CORS, and validate configuration.
